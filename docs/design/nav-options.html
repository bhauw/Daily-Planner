A

Sidebar rail

Recommended

One window, a persistent rail, and the assistant stays docked on the right no matter which surface you're in. Today is your existing three-column shell; Mail, Calendar and Tasks are full workspaces you switch into. The rail is also where unread and pending counts live, so you can see what's waiting without leaving the day.

B

Separate windows

Most macOS-native

Each workspace is a real window you can throw onto a second monitor — planning shell on one screen, draft workbench on the other. Genuinely the most Mac-like answer, and the best one if you work on an external display. The cost is that WKWebView makes multi-window meaningfully harder: each window is its own web view with its own state, so they need a shared store and explicit sync.

C

Expand in place

Fewest concepts

Click a column and it grows to fill the shell as the full workspace, then collapses back. You never lose your place and there's no navigation model to learn. The catch: there's nowhere to put a persistent nav, so the three source workspaces are only reachable from the columns that happen to reference them — and a draft workbench isn't any column's child.

D

Top tabs

Simplest to build

Browser-style tabs in one window. Fastest to implement and instantly familiar — but it spends your vertical space on chrome, and it's the weakest at keeping the day visible while you work a surface, which is the whole reason the planner exists. Your brief's rule that mode switching must not reset mental context is hardest to honour here.

Two things I found in the code while building this. Your brief says Finance should be lavender, but PlannerPalette.swift returns the career colour (yellow) for .finance — so finance items are currently mis-coloured. And personal uses NSColor.magenta (#FF00FF), which passes contrast at 5.3:1 but is the one harsh note in an otherwise calm palette.
